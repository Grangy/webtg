# ТЗ: API бэкенда (grangy.ru) для веб-приложения MaxGroot

Документ описывает контракт API, который потребляет веб-приложение, текущие проблемы и рекомендации по улучшению.

---

## 1. Базовые параметры

| Параметр | Значение |
|----------|----------|
| Base URL | `process.env.API_URL` (по умолчанию `https://grangy.ru/api`) |
| Аутентификация | Заголовок `X-Webapp-Secret: <API_SECRET>` |
| Формат | JSON |

## 2. Эндпоинт: баланс пользователя

### Запрос

```
GET /user/:telegramId/balance
X-Webapp-Secret: <secret>
```

### Контракт (реализовано на бэкенде)

Ответ API стабилен и однозначен:

| Поле | Смысл |
|------|--------|
| **totalBalance** | Текущий доступный баланс (из БД) — единственный источник правды для списаний и отображения. |
| **balance** | Основной баланс: пополнения, списания за подписки, админ-промо (без реферального). Считается как totalBalance − balanceReferral. |
| **balanceReferral** | Сумма, зачисленная с рефералов (только зачисленные бонусы). |

Веб-приложение берёт для отображения «доступно к списанию» поле **totalBalance**; при его наличии дополнительная логика не нужна.

### Пример ответа

```json
{
  "ok": true,
  "data": {
    "totalBalance": 261,
    "balance": 150,
    "balanceReferral": 111
  }
}
```

**Правило:** в приложении для отображения «доступно к списанию» всегда используем **`totalBalance`**. При его отсутствии в ответе (старые версии API) приложение считает: totalBalance = balance + balanceReferral.

## 3. Эндпоинт: отладка баланса (опционально)

### Запрос

```
GET /user/:telegramId/balance/debug
X-Webapp-Secret: <secret>
```

Используется для проверки и аудита. Желательно, чтобы в ответе были:

- Сырые значения с БД/сервиса (основной, реферальный, блоки, списания).
- Итоговый `currentBalance` или `totalBalance`, который бэкенд считает «правильным» для отображения.

Это позволит сверять логику веб-приложения с бэкендом.

## 5. Как проверить, что отдаёт API (аудит)

В веб-приложении добавлен эндпоинт проверки:

```
GET /api/user/:telegramId/balance/audit
```

Он вызывает бэкенд `/user/:id/balance` и при наличии — `/user/:id/balance/debug`, и возвращает:

- сырые ответы бэкенда;
- какие ключи пришли в ответе balance;
- как приложение их интерпретирует (main, referral, ourComputedTotal и формулу).

Пример вызова (локально или на проде):

```bash
# Локально (нужен запущенный сервер и валидный telegramId)
curl "http://localhost:3000/api/user/123456789/balance/audit"

# Или через тестовый скрипт (добавить в scripts при необходимости)
TELEGRAM_ID=123456789 node scripts/test-balance.mjs
```

По ответу audit можно понять:

- приходит ли `totalBalance` / `currentBalance`;
- что именно в `balance` (уже общий или только основной);
- не считается ли на бэкенде «потраченный» баланс в `balance` — и тогда запросить у бэкенда отдельное поле «доступный» или явный `totalBalance`.

## 6. Итог по балансу

- **Текущая проблема:** приложение не знает, что такое `balance` (доступный или уже с учётом списаний), и вынуждено комбинировать `balance + referral`, из-за чего возможны расхождения (372 вместо 261 или уход в минус).
- **Решение:** бэкенд должен всегда отдавать **одно явное поле общего доступного баланса** (рекомендуемое имя: **`totalBalance`**), рассчитанное на стороне бэкенда. Остальные поля — для детализации (основной, реферальный) и отладки.

После введения стабильного контракта с `totalBalance` веб-приложение можно упростить: всегда брать отображаемый баланс из `totalBalance`, без эвристик.

---

## 7. Итого: что сделано для правильных расчётов

### На бэкенде (сделано)

- В ответе `GET /user/:telegramId/balance` возвращается **totalBalance** (текущий доступный баланс из БД) — источник правды для отображения и списаний.
- **balance** — основной баланс (totalBalance − balanceReferral).
- **balanceReferral** — сумма с рефералов. В боте используется то же значение из БД (user.balance = totalBalance).

### В веб-приложении

- В **sync** приоритет: `totalBalance` → `currentBalance` → иначе `balance + referralBalance` (см. `src/app/api/user/[telegramId]/sync/route.ts`).
- Для отображения «доступно к списанию» используется значение из sync (уже берётся totalBalance при наличии).
